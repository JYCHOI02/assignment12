# 경력기술서

과제 하나당 한 줄 제목 + 어느 능력에 해당하는지 + 상황·행동·결과(STAR). 모두 9번 서사 문서 강점지도표(T01~T08 과제 목록)와 리추얼 기록에서 가져왔고, 날짜·수치가 불확실한 부분은 넣지 않았습니다.

## 1. [자기동기력] 게임 프로젝트: 버그 수정과 플레이테스트 기반 밸런싱

- **한 줄:** AI 제안에 기대지 않고 원인을 직접 찾아낸 문제 해결
- **상황:** 게임 개발 과제를 하던 중, 타워 선택 UI와 인터페이스 요소가 서로 겹쳐 보이는 예상치 못한 버그가 생겼습니다.
- **행동:** AI가 제안한 수정안을 그대로 쓰지 않았습니다. 버그가 왜 생기는지 직접 추적해 원인을 찾고 고쳤습니다. 게임 밸런스도 수치로만 정하지 않고, 직접 플레이해 보면서 체감에 맞게 조정했습니다.
- **결과:** 버그 없이 안정적으로 작동하는 게임을 완성했습니다.
- **출처:** 9번 서사 문서 강점지도표 "강점 1·2"의 T02.

## 2. [자기조절력] 데이터 대시보드: 렌더링 부하를 고려한 조회 범위 설계

- **한 줄:** 하고 싶은 것보다 필요한 것을 먼저 고른 설계 판단
- **상황:** 데이터가 쌓일수록 SVG 차트가 그려야 할 요소가 늘어나 화면이 느려질 수 있는 구조였습니다.
- **행동:** 전체 기간을 모두 보여주고 싶은 욕심을 내려놓았습니다. 대신 조회 범위를 최근 90일로 제한하기로 직접 정해 적용했고, 기능을 늘리는 것보다 안정적으로 동작하는 것을 우선했습니다.
- **결과:** 데이터가 늘어나도 안정적으로 동작하는 대시보드를 완성했습니다.
- **출처:** 9번 서사 문서 강점지도표 "강점 2"의 T05.

## 3. [대인관계력] ALEPH 보안 팀 프로젝트

- **한 줄:** 혼자 하던 방식에서, 서로의 빈 곳을 채우는 협업으로
- **상황:** 저는 원래 혼자 작업하는 데 익숙했습니다. ALEPH 보안 팀 프로젝트에서는 팀원들과 역할을 나눠 함께 작업했습니다.
- **행동:** 제가 모르는 부분은 동료에게 도움을 받았고, 반대로 동료에게 필요한 부분은 제가 채웠습니다. 동료가 작업에 필요한 웹훅 메시지를 요청했을 때도 바로 공유해, 동료가 기다리지 않고 작업을 이어 갈 수 있게 했습니다.
- **결과:** 동료에게서 "공유 요청하자마자 공유해주셔서 감사합니다"라는 말을 들었습니다. 서로 부족한 부분을 보완하며 혼자 할 때보다 협업이 더 좋다는 것을 직접 느꼈습니다.
- **출처:** 리추얼 기록 2026-10월 항목(동료 감사 기록, 이름은 가려져 있음).

## (참고) 넣지 않은 항목

- T04(환율 대시보드, WTI API 장애 대응)는 9번 서사 문서 각주에 "납기를 지킨 것은 아니고, 오류를 파악·수정한 예시라 삭제함"이라고 작성자 본인이 직접 취소선을 그어 둔 항목이라 **경력기술서에 넣지 않았습니다.** 넣고 싶으시면 "납기 준수"가 아니라 "장애 상황에서 대안을 찾아 전환"으로만 쓸 수 있습니다.
- T01(첫 웹 배포), T03(UI 재구성), T06~T08(Plan/Do/See, 인증, 패스키)은 사용하지 않았습니다. 자기소개서 본문에 이미 쓴 내용(T01)과 겹치거나, 세 능력에 깔끔하게 걸리는 장면을 고르라는 지침에 따라 뺐습니다. 더 넣고 싶은 과제가 있으면 알려주세요.
